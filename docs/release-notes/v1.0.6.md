# Pulse 1.0.6

## Highlights

- Keep using Pulse for a 30-day trial, up to 1,000 successful model refreshes, then activate through MLBS.
- Register, sign in, view your licence profile and sign out through the shared MLBS desktop client. Pulse uses its own PULSE product and saved identity.
- Review recorded health scans, trends, summaries and comparisons with paginated history.
- View published ACC model information alongside local health checks when Autodesk access is configured.

## Packaging

- Separate Suite module payloads for Revit 2024 (.NET Framework 4.8), 2025/2026 (.NET 8) and 2027 (.NET 10), each built against that year's API.
- Production MLBS endpoint: `https://mms.modena-app.co.za/mlbsapi/`; PULSE product code: `50554C5345`; request timeout: 30 seconds.
- Existing trial start dates are preserved. Users already beyond day 30 require activation; paid access remains independent of local trial usage.
- Each `ModelHealthChecker-1.0.6-suite-RevitYYYY.zip` contains the module files directly. The combined `suite-payload.zip` contains `Runtime/YYYY/Modules/ModelHealthChecker` and year-specific catalog descriptors.
- Suite archives omit local APS credentials. Provision existing `APS_CLIENT_ID` / `APS_CLIENT_SECRET` variables or an external `aps.json` using the supported credential provider. They do not install a standalone Revit manifest.
- Build standalone artifacts with `scripts/Build-Release.ps1 -Version 1.0.6`. Build Suite archives with `scripts/Build-SuiteRelease.ps1 -Version 1.0.6 -SkipBuild` after the year-specific payloads are staged.

## Validation

- Licensing regression tests: 13 passed.
- Suite packaging verifies compiled version, the 30-day trial constant, exact Revit API references and bundled MLBS client for every year; archive hashes accompany the release.
- Payload compilation and package checks do not establish native Revit workflow acceptance or Authenticode signing.

## Known issues

- Production product resolution succeeded on 23 November 2026, but licence and subscription balance queries returned HTTP 502 `BALANCE_LOOKUP_FAILED` from the ledger lookup path. Production paid access needs a successful end-to-end retest.
- Paid verification uses MLBS sign-in and can consume a subscription token, including checks before refreshes and automatic refreshes. A successful staging sign-in on 12 November consumed one token. Charging policy needs confirmation before customer rollout.
- ACC live-account workflows and native testing in each supported Revit year remain separate acceptance checks. These module payloads are unsigned inputs for the Suite build; apply the Suite's normal signing and acceptance process.
